## 2. Supuestos, dependencias y exclusiones

### Supuestos de arquitectura
- Stack objetivo de Sprint 1: **Next.js 16, React 19, Tailwind CSS v4, shadcn/base-nova, Supabase PostgreSQL 15 + PostgREST y static export en Cloudflare Pages**.
- El frontend mantiene el patron actual de `fetch()` directo a PostgREST, sin incorporar `@supabase/supabase-js` en Sprint 1.
- Las rutas actuales son `/`, `/courses`, `/courses/[institution]/[slug]`, `/compare`, `/privacidad`, `/terminos`. El documento menciona `/programas/[slug]`, pero la pagina de detalle completa queda fuera de Sprint 1 salvo enlaces existentes hacia el detalle actual.
- La implementacion visual se adapta desde los HTML aprobados, preservando SSR donde sea posible y aislando interactividad con `'use client'` solo en busqueda, filtros, chips, selector de moneda, modales y acciones de cards.
- Los cambios de base de datos deben versionarse como migraciones, validarse primero en Supabase Free/Certificacion y luego promoverse a Pro solo con aprobacion posterior.
- Para administracion en static export, no se puede exponer secret key en browser. Cualquier escritura privilegiada requiere RLS/RPC segura o mecanismo equivalente aprobado antes de implementar.

### Exclusiones explicitas de Sprint 1
- API de tipo de cambio real: queda para Sprint 3; Sprint 1 solo contempla selector visual o tasa estatica si se decide mostrarla.
- Pagina completa `Como funciona`.
- Pagina completa de detalle SEO `/programas/[slug]` y migracion de ruta canonica; se conserva la ruta actual si se enlaza desde cards.
- Entrega en tiempo real de leads patrocinados por email/webhook configurable; Sprint 1 puede preparar campos/flags, pero no implementar automatizacion comercial completa.
- Scraping automatico de logos; se admite fallback por iniciales/logo placeholder.
- Sistema real de resenas; estructura vacia o existente queda sin expansion funcional.
- Busqueda semantica con embeddings/pgvector.
- QA de carga masivo, automatizacion de backlog, creacion de tareas o ejecucion de scripts.
- Disponibilidad completa de 3 estados como sistema final y alertas admin de >60 dias quedan fuera salvo campos base/visualizacion inicial si dependen de CA2/CA4/CA10.

## 8. Riesgos arquitectonicos y mitigaciones

1. **Static export limita endpoints server-side tradicionales.**
   *Mitigacion:* usar PostgREST/RPC con RLS estricta; no exponer secret keys; cualquier admin privilegiado requiere mecanismo aprobado y compatible con Cloudflare Pages.

2. **Next.js 16 + React 19 con componentes client-heavy puede degradar hidratacion.**
   *Mitigacion:* separar shell/server components de componentes interactivos (`HomeContent`, filtros, chips, modales) y usar `'use client'` solo donde sea obligatorio.

3. **`generateStaticParams` sin paginacion puede truncar detalle para catalogos >1000.**
   *Mitigacion:* Sprint 1 no depende de nuevas rutas detalle; documentar deuda y no prometer SEO completo de detalle hasta corregir paginacion.

4. **`generateMetadata` por slug solamente puede colisionar entre instituciones.**
   *Mitigacion:* no migrar canonicals en Sprint 1; mantener alcance en Home/Resultados y planificar correccion posterior.

5. **Colision entre estados ETL y estados editoriales.**
   *Mitigacion:* usar nombres no ambiguos como `publication_status`/`data_quality_status` o equivalentes, sin reutilizar `status` operativo de tablas intermedias.

6. **Reactivacion de schedules con perfiles no afinados puede generar ruido o bloqueos.**
   *Mitigacion:* respetar gates por institucion, circuit breaker, limites por corrida y priorizar enfoque quirurgico sitemap/RSS para evitar Cloudflare/Captcha.

7. **RLS y escrituras anonimas de leads/ratings/reviews pueden recibir spam.**
   *Mitigacion:* mantener `INSERT` anon minimo, validaciones defensivas, no lectura publica de PII, y separar entrega real-time de leads patrocinados para sprint posterior.

8. **Discrepancia PDF vs base interna sobre FG3.**
   *Mitigacion:* tratar la base interna como fuente del estado real: FG3 esta documentado como desactivado aunque el PDF lo mencione como existente; Sprint 1 puede formalizar/reactivar con aprobacion del Hito 1.
