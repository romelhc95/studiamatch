### Contrato DB/RLS
- `courses.publication_status`: valores `borrador`, `pendiente_revision`, `publicado`, `despublicado`.
- `courses.data_quality_status`: valores `pendiente`, `completo`.
- `courses.missing_fields`: arreglo JSONB para campos criticos faltantes.
- `courses.field_sources`: objeto JSONB para origen de cada campo, por ejemplo scraping, LLM o manual.
- `courses.manual_updated_at`: timestamp de curacion manual para Hito 3.
- `courses.is_sponsored`, `courses.sponsorship_priority`, `courses.sponsorship_label`: base de patrocinio para Hito 5.
- `leads.lead_source_type`: clasificacion base `organic` o `sponsored`; anon/authenticated quedan forzados a `organic` por RLS.
- `leads.course_id`: si viene informado en un insert publico, debe apuntar a un curso activo, verificado, publicado y de una institucion con `production_enabled=true`.
- La migracion elimina policies legacy permisivas `"Public read for courses"` y `"Anyone can insert leads"` antes de crear las policies endurecidas para evitar combinacion OR de RLS.
- `courses.start_date` y `courses.start_date_text` se reutilizan como fecha estructurada/texto original de proximo inicio; no se crea `next_start_date`.
