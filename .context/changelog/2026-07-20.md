## Dispatcher de agentes e higiene del repositorio

- Se mantiene la decision operativa de conservar tres ramas/ambientes permanentes: `desarrollo` con Supabase Free, `certificacion` con Supabase Free y `main` con Supabase Pro.
- Se implemento el dispatcher asistivo en `scripts/maintenance/agent_dispatcher.py` con tests recurrentes en `tests/release_gate/test_agent_dispatcher.py`.
- El dispatcher no esta activado como gate bloqueante; su activacion en CI requiere aprobacion posterior explicita.
- Se documento la politica de higiene del repositorio en [[../operaciones/politica_higiene_repo]].
- Se documento el inventario inicial de limpieza en [[../operaciones/inventario_limpieza_repo_20260720]].
- Se reforzo `sync_vector_worker.py` para no republicar cursos que ya existen con `is_active=false` por curacion manual.
- Los skips por curso desactivado registran `metadata.skip_reason` para trazabilidad.
- Se acoto `NEXT_SUPABASE_ACCESS_TOKEN` a workers canary explicitos mediante `STUDIAMATCH_CANARY_WORKER=1`.
- El canary local retira `NEXT_SUPABASE_SECRET_KEY` del entorno del worker cuando usa access token restringido.
- Se restringio la postcondition de canary guards a la consulta exacta `SELECT guards_valid FROM public.verify_release_canary_guards()`.
- Se actualizo la documentacion tecnica para reemplazar la referencia a `upsert` directo por escritura protegida por `is_active`.
- El dispatcher rechaza rutas no canonicas en `--changed-file` y `--changed-files`.

## Extension dispatcher implementation mode

- Se agrego `--mode implementation` al dispatcher para enrutar roles de desarrollo antes de implementar un hito aprobado.
- El modo implementation exige tarea aprobada y coincidencia exacta con `--approved-hito`.
- Si la tarea declara archivos concretos, el dispatcher bloquea changed files fuera de alcance con `NO_GO`.
- El modo implementation respeta `skill_principal`, `skills_apoyo` y `gate_obligatorio` de la tarea para definir roles.
- Se agregaron tests recurrentes para tarea aprobada, tarea pendiente, hito incorrecto y archivos fuera de alcance.

## Backlog por requerimiento

- Se formalizo que las tareas viven en `.context/backlog_tareas/<requerimiento_slug>/` y no directamente en la raiz del backlog.
